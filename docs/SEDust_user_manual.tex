\begin{abstract}
\noindent
This manual describes the model-agnostic dust library under \code{SEDust/sed/}.
It computes the infrared emission spectrum \emph{and} the transport optics
(extinction, scattering, asymmetry) of a dust mixture for an arbitrary local
radiation field, and is intended to be linked into a Fortran 3D
radiative-transfer (RT) code. It handles several dust models as peers --- the
HD23 \emph{astrodust}+PAH model, the Draine \& Li (2007) silicate+carbonaceous
model, the Mathis, Rumpl \& Nordsieck (1977) graphite+silicate model, the
Zubko, Dwek \& Arendt (2004) BARE-GR-S model, and arbitrary file-defined
models --- through one object type, one emission call, and one extinction
call. The numerically validated stochastic-heating solver is reused
unchanged; the library is an additive layer on top of it.

This version is the \textbf{scalar} branch (v1.00): unpolarized cross sections
and unpolarized emission. There is no polarized-transfer API here --- no
dichroic extinction matrix, no aligned-grain scattering matrix. Use v1.20 for
those.
\end{abstract}

\section{Overview}

A \emph{dust model} is represented by a single derived type,
\code{dust\_model\_t}. You build it once (per RT run), then call
\code{dust\_emission} once per RT cell with that cell's local mean intensity:

\begin{lstlisting}
use dust_lib
type(dust_model_t)    :: m
real(wp), allocatable :: J_lam(:), lamI_total(:)

call build_dust(m, 'astrodust', '../data')                       ! once
allocate(J_lam(m%NLAM), lamI_total(m%NLAM))
do icell = 1, ncells
   ! ... assemble J_lam(:) (mean intensity on the grid m%lam) for this cell ...
   call dust_emission(m, J_lam, lamI_total)                      ! per cell
   ! ... lamI_total(:) is lambda*I_lambda / N_H for the cell ...
end do
\end{lstlisting}

\paragraph{Design.} The library wraps the existing, FIR-validated solver core
(\code{sed\_grain\_loop}, \code{calc\_Teq}, \code{calc\_P}) without modifying it.
A model is a set of grain \emph{populations} (one per species and charge state),
each carrying its own size distribution, absorption cross sections, enthalpy, and
Planck-integral tables. \code{dust\_emission} loops the populations through the
solver and sums their emission into named output \emph{channels}.

\paragraph{One active model at a time.} The module-global grids
(\code{lam}, \code{T\_first}, $\dots$) hold the \emph{currently built} model's
working set. Calling \code{build\_*} makes that model active. This is sufficient
for an RT run that uses a single dust model; to switch models, rebuild.

\section{Building the library}\label{sec:build}

One archive:
\begin{lstlisting}[style=sh]
cd SEDust/sed && make libsedust.a         # the library archive
\end{lstlisting}
Nothing in it reaches the T-matrix, so \code{SEDust/tmatrix} need not be built
for the default, non-ionizing $Q$ table (1129 wavelengths,
\SIrange{0.0912}{39810}{\micro\meter}).  The separately shipped
\code{q\_astrodust\_P0.20\_Fe0.00\_1.400\_euv.dat} has 1762 wavelengths and
reaches \SI{1e-4}{\micro\meter}; explicit EUV commands select that file.
What follows applies to a model that forms a band below the table it was given.
Built from this archive, such a model
\emph{refuses} the spheroid (\code{euv\_tmatrix = .true.}, the default whenever
\code{lam\_min} is given) with \code{status = 6}, rather than answering with a
different particle behind the caller's back; \code{euv\_tmatrix = .false.} asks
for the volume-equivalent sphere explicitly.

A host that wants such a band on the spheroid of the $Q$ table
(\S\ref{sec:euv-shape}) builds the T-matrix into the \emph{same} archive, so the
link line below does not change:
\begin{lstlisting}[style=sh]
cd SEDust/tmatrix && make libtmatrix.a            # T-matrix
cd SEDust/sed     && WITH_TMATRIX=1 make libsedust.a
\end{lstlisting}
and names the spheroid once, before the model is built:
\begin{lstlisting}
use euv_astrodust_tmatrix, only: use_tmatrix_euv_band_optics
call use_tmatrix_euv_band_optics()
\end{lstlisting}
\code{SEDust/sed/build\_lib.sh} is the same two builds as a standalone script,
for an RT tree that carries its own copy of \code{sed/src/}; it writes
\code{sed/lib/} and takes \code{WITH\_TMATRIX=1} the same way.

Of the CLI drivers, \code{calc\_sed.x astrodust} and \code{calc\_kext.x} are built
against \code{libtmatrix.a} and make that call themselves --- they are the two
that would compute an astrodust EUV band if one ever formed. \code{calc\_sed.x dl07} and
\code{calc\_sed.x zubko} need no T-matrix: those models' optics reach past the Lyman
limit on their own.

The compiler is \code{gfortran}. The default flags are
\code{-O3 -ffree-line-length-none -fopenmp} plus a warning set --- deliberately
\emph{portable}, so that a \code{libsedust.a} built on one node runs on any
other. A \code{-march=native} line is present but commented out; enabling it can
change the last digits through FMA contraction. \code{libsedust.a} is a static
archive of all library objects; the Fortran \code{.mod} files are written
alongside it in \code{SEDust/sed/}. The \code{Makefile} declares
\code{.NOTPARALLEL}, because every executable recipe compiles the shared module
sources into the same directory and \code{make -j} would race on the
\code{.mod} files.

                     [, kext_path] [, lam_min] [, include_euv])
\end{lstlisting}

\begin{itemize}
\item \code{NT}, \code{T\_lo}, \code{T\_hi}: number and range [K] of the internal
      temperature grid (typical \code{200, 2.7, 5000}).
\item \code{sd\_index} (DL07): WD01 size-distribution index --- \code{7} =
      MW $R_V{=}3.1$, $q_{\rm PAH}{=}4.58\%$; \code{29/30/31} = LMC2; \code{32} = SMC.
\item \code{U} (DL07): ISRF intensity scaling (the DL07 reference uses $U{=}1$).
\item \code{data\_dir} (Zubko / files): directory holding the data files, e.g.
      \code{data/zubko/}.
\item \code{status} (optional, all builders): error report; see
      \S\ref{sec:status}. When present, a missing or malformed input file is
      reported through it and the model is not built, so an RT host can recover.
      \code{build\_dust} maps every builder's own stage number onto \emph{one}
      vocabulary, so a host on the single entry point does not branch on the
      model name to read a code, and takes an optional \code{message} carrying
      the reason in words --- what an MPI host prints before a collective abort.
\item \code{data\_dir} (\code{build\_dust}): the data root for the whole library
      while the build runs. The dielectric functions, the default extinction
      curves and the stored cross-section tables all resolve inside it, so a
      host may call \code{build\_dust} from any working directory with an
      absolute path, and a file that cannot be read arrives as a \code{status},
      never as a runtime abort. A path the caller names itself is used as given
      and never composed with the root. A host that calls the builders
      directly sets the root once with \code{sed\_set\_data\_root}, re-exported
      from \code{dust\_lib}.
\item \code{stored\_q\_dir} (optional, DL07 and MRN): where this model's stored cross
      sections come from. Omitted, the model's own directory under the data
      root, with the \code{/qtable} of an HDF5 \code{qtable\_path} ahead of it.
      Passed blank, nothing stored is read and every optic is solved from the
      dielectric functions.
\item \code{pah\_xsec} (optional, DL07): which vintage of the PAH cross
      sections the carbonaceous channel is built on, \code{'dl07'} (default,
      the DL07 paper's own prescription) or \code{'ld01'} (Li \& Draine 2001);
      it is what the \code{ld01} keyword of the CLI drivers sets. Any other
      string is refused with \code{status = 8} rather than defaulted.
\item \code{qtable\_path} (optional, Zubko): the model's HDF5 product, which is
      where its stored cross sections then come from. This is an argument
      rather than hidden state so that a program writing \code{/kext} into a
      product takes its optics from the \code{/qtable} of that same product.
\item \code{lam\_min} (optional, astrodust, DL07 and MRN): shortest wavelength
      [\um] the model must cover, for a host that transports ionizing
      radiation. See \S\ref{sec:euv}. \textbf{Omitting it reproduces the previous
      behavior exactly} --- the grid, and every number derived from it, is
      unchanged. For astrodust what it does depends on the $Q$ table: on the
      default 1129-wavelength one a floor below $0.0912$\um\ builds a band,
      while the \code{\_euv} table already reaches the short end of the DH21
      dielectric function, so there every value that is not refused falls
      inside the table and prepends
      nothing. DL07 can be carried to $6.205\times10^{-5}$\um\ below either, because
      its D03 optical constants reach past the table.
\item \code{astrodust\_index\_path} (optional, astrodust only): the dielectric
      function the model is made of. It is read to decide how far
      \code{lam\_min} may reach, and it would supply the optics of a band below
      the $Q$ table if one ever formed. It must be the file
      \code{qtable\_path} was computed from --- same porosity, iron fraction and
      axial ratio --- or the model changes material at the seam. Omitted, it is
      the default that pairs with the shipped $Q$ table:
\begin{lstlisting}[style=sh]
data/dielectric/index_DH21Ad_P0.20_0.00_1.400   <->
data/astrodust/q_astrodust_P0.20_Fe0.00_1.400.dat
\end{lstlisting}
\item \code{kext\_path} (optional, all builders): the precomputed
      size-integrated extinction table this model will serve through
      \code{dust\_extinction} (\S\ref{sec:ext}). The builder loads it, because
      the path is relative to \code{sed/} and a host is free to change
      directory once the model is built. Naming a file is a contract: if it
      cannot be read the \emph{build fails}. Omitted, the model's default table
      (Table~\ref{tab:models:kext}) is tried, and a default that is not there
      leaves the model with no extinction to serve --- but the build succeeds,
      so a driver that only computes emission still runs.
\item \code{euv\_tmatrix} (optional, astrodust only, default \code{.true.}):
      how the extended band's optics are computed. \code{.true.} is the
      T-matrix on the same $b/a = 1.400$ oblate spheroid as the $Q$ table, and
      requires a library built with the T-matrix and the one registration call
      of \S\ref{sec:build} --- without them the build fails with
      \code{status = 6} instead of substituting a sphere silently.
      \code{.false.} asks for the volume-equivalent-sphere Mie approximation,
      which is far cheaper and about 2\% low in the geometric-optics limit, and
      needs no T-matrix at all. See \S\ref{sec:euv-shape}. Ignored when
      \code{lam\_min} asks for no extension --- which, with the shipped $Q$
      table, is every legal request, so \textbf{this argument currently selects
      nothing}. It is kept for a model whose optics table stops short of its own
      dielectric function.
\end{itemize}

\subsection{The MRN model}\label{sec:mrn}

\code{build\_mrn} is the classical Mathis, Rumpl \& Nordsieck (1977) mixture:
graphite and astrosilicate spheres, one power law per material,
%
\begin{equation}
  \frac{dn_i}{da} = A_i\, n_{\rm H}\, a^{-3.5},
  \qquad 0.005\,\um \le a \le 0.25\,\um,
  \label{eq:mrn}
\end{equation}
%
cut sharply at both ends. Equation~\eqref{eq:mrn} is Draine \& Lee (1984,
eq.~5.1); the cutoffs are MRN's own estimates, which DL84 held fixed. There are
\emph{no} PAHs in it --- the smallest grain is a 50\,\AA\ graphite sphere and
the $2175$\,\AA\ feature is graphite's --- so the emergent SED carries no
aromatic emission features at all. That is the model, not a gap in the solve.

\paragraph{The normalization.} $\log_{10} A_{\rm gra} = -25.16$ and
$\log_{10} A_{\rm sil} = -25.11$, in cm$^{2.5}$/H: the abundances DL84 \S Va
adopted after fitting the Savage \& Mathis average extinction curve with their
own dielectric functions. They are what Draine's own published curve
\code{kext\_albedo\_MRN} is the size integral of --- his parameter file for it
states the grain volumes per H, $2.49\times10^{-27}$ and $2.79\times10^{-27}$
cm$^3$/H, and integrating $(4\pi/3)a^3\,A_i a^{-3.5}$ over $[0.005, 0.25]\,\um$
turns those into exactly these two $A_i$. That curve ships as
\code{data/release/kext\_albedo\_MRN} and \code{calc\_kext.x mrn} prints the
point-by-point comparison against it at the end of every run.

\noindent The same sentence of DL84 quotes MRN's \emph{own} pair,
$A_{\rm sil} = 10^{-25.10}$ and $A_C = 10^{-25.13}$ after adjustment to the
Bohlin, Savage \& Drake (1978) $N_{\rm H}/E(B-V)$. They differ by 7\% in the
graphite abundance and are \emph{not} offered here: this model is the one the
reference curve tests.

\paragraph{Optics, enthalpy and grid.} Mie on the Draine (2003) dielectric
functions --- the same \code{q\_silicate\_full} and \code{q\_graphite\_full}
the DL07 model's silicate and graphite come from, graphite on the
random-orientation average $\tfrac13\,E\!\parallel\!c + \tfrac23\,E\!\perp\!c$.
MRN themselves used Wickramasinghe's optical constants; DL84 recomputed this
size distribution on theirs, and D03 is the current revision of those. The
enthalpies are the Draine \& Li (2001) heat capacities, and the densities
$3.5$ and $2.2$\,g\,cm$^{-3}$ --- the values those capacities and the D03
optics are both defined with. Because the optics are dielectric-function Mie at
every wavelength, the model takes only a wavelength \emph{axis} from its
product, exactly as DL07 does, and \code{lam\_min} extends the grid rather
than the physics. The radius grid is the model's own: 70 log-spaced points with
the two cutoffs of eq.~\eqref{eq:mrn} on its ends.

\paragraph{What the comparison against Draine's curve shows.} From the far
ultraviolet through $\sim20\,\um$ --- the whole band the size distribution was
fitted in --- our $C_{\rm ext}$/H agrees with \code{kext\_albedo\_MRN} to
$1$--$2\%$. Longward of $\sim60\,\um$ ours is lower, by $22\%$ at
$100\,\um$ and $18\%$ at $1000\,\um$. That is an optical-constants vintage
difference and not a defect here: Draine's MRN table is dated December 2002 and
its silicate is his \code{ICOMP=7} ``smoothed UV silicate'', while ours is the
2003 astrosilicate. His own two curves for the \emph{same} power law and the
same $a_{\max}$ at essentially the same total volume per H --- the 2002 MRN
table against the D03 \code{amax\_0.25um} one --- differ by $+23\%$ at
$100\,\um$ and $+15\%$ at $1000\,\um$ in the same direction. Our D03 optics
are the ones checked against his D03-vintage DL07 table, which they reproduce
to $0.01\%$ in the same band (\S\ref{sec:ext}).

\paragraph{Energy is conserved.} Solved with \code{equil} the model emits
$0.99987$ of what it absorbs from the Mathis field, and with \code{draine}
$1.00003$ --- the same $10^{-4}$ closure the DL07 model gives ($0.99991$).
Under the default \code{heuristic} solver it emits $0.949$, against DL07's
$0.977$; that shortfall is the heuristic solver's own accuracy on this size
distribution, whose smallest grains are stochastically heated $50$\,\AA\
graphite spheres, and not a property of the model
(\S\ref{sec:solver}).

\paragraph{Two routes to the Zubko model.} \code{build\_zubko} evaluates the ZDA
log-polynomial size-distribution \emph{formula} (coefficients read from
\code{ZDA\_BARE\_GR\_S\_Config.dat}) on the optics-table radii;
\code{build\_from\_files} with \code{data/zubko/zubko\_descriptor.txt} instead
interpolates the \emph{tabulated} \code{SzDist} files onto the same radii. The
two shapes agree to $\sim10^{-5}$, but the distributed tables carry a
normalization that sits below $A\,g(a)$ of the config by 0.79\% (PAH), 1.13\%
(graphite) and 0.41\% (silicate), and they are sampled at only 24 / 62 / 63
radii, so interpolation near $a_{\max}$ adds a little more. Together this moves
the size-integrated $C_{\rm ext}$ by up to 2.10\% (median 1.02\%). \textbf{The
formula is the default and is faithful to the ZDA definition}; the tabulated
route exists to reproduce the benchmark's own size grid.

\paragraph{The ZDA optics are a homogeneous-sphere Mie calculation, and that was
checked.}\label{sec:zubko-mie}
The three ZDA optics tables are the model definition, so nothing is recomputed at
run time. What they \emph{are}, however, is stated in two independent places and
was verified here. Zubko et al.\ (2004, \S3) write that for the bare silicate,
graphite and amorphous-carbon particles ``the extinction and absorption cross
sections were calculated using Mie theory for spherical dust particles (Bohren
\& Huffman 1983)'' --- the effective-medium step of that paper applies to its
\emph{composite} models only. Each shipped file repeats it: the silicate and
graphite headers name the dielectric function they were computed from
(Draine's \code{eps\_Sil} and \code{eps\_Gra}), while
\code{PAH\_28\_1201\_neu.dat} names the Li \& Draine (2001) and Draine \& Li
(2007) absorption cross sections instead --- that component is not Mie and has
no refractive index to be recomputed from.

Recomputing \code{suvSil\_121\_1201.dat} with the library's own
Bohren--Huffman Mie on Draine's published \code{eps\_Sil}, over all
$121\times1201$ cells:

\begin{itemize}
\item at a fixed wavelength the ratio $Q^{\rm ours}/Q^{\rm table}$ is
      \emph{independent of grain radius to four digits} across the whole
      $3.55\times10^{-4}$--$100$\um\ range (e.g.\ $1.0171$ at $9.9$\um\ and
      $1.0067$ at $99.8$\um\ at every radius);
\item $\langle\cos\theta\rangle$ agrees to $\sim10^{-4}$.
\end{itemize}

\noindent Both are properties of the sphere and the size parameter, so they
settle the question the comparison was asked: the table is a homogeneous-sphere
Mie calculation and the library reproduces it. What is left is a purely
wavelength-dependent factor --- mean $|\Delta Q_{\rm abs}| = 0.59\%$ over
10--100\um, $1.7\%$ over 1--10\um, rising at the extreme long-wavelength end
--- and a radius-independent, wavelength-dependent residual can only come from
the refractive index, not from the scattering solution. The published
\code{eps\_Sil} is tabulated on a different wavelength grid from the table
(200 per decade, ending at $10^3$\um, against 171 per decade to $10^4$\um), so
the file the table's generator actually evaluated was a resampled and extended
copy that is not the one distributed. Reproducing the tables to better than a
percent would need that copy; nothing in SEDust depends on it, because the
tables themselves are what every Zubko build reads.

\section{Computing emission}

\subsection{Single-cell exact solve}

\begin{lstlisting}
call dust_emission(m, J_lam, lamI_total [, lamI_chan] [, status])
\end{lstlisting}
\begin{itemize}
\item \code{J\_lam(m\%NLAM)}: the local \emph{mean intensity} on the grid
      \code{m\%lam} [\um]. For a scaled Mathis ISRF use
      \code{call J\_Mathis(U, m\%lam, J\_lam)} from module \code{radfield}.
\item \code{lamI\_total(m\%NLAM)}: the summed SED, \lamIlam$/\Nh$
      [\,erg\,s$^{-1}$\,cm$^{-2}$\,sr$^{-1}$\,H$^{-1}$\,] --- the HD23 convention.
\item \code{lamI\_chan(m\%NLAM, m\%n\_channel)} (optional): the SED of each channel.
\item \code{status} (optional): error report; see \S\ref{sec:status}.
\end{itemize}

\subsection{Solver choice (\code{m\%stoch\_method})}\label{sec:solver}

The field \code{m\%stoch\_method} selects how each grain is heated
(Table~\ref{tab:solver}); \code{dust\_emission} honors it.

\begin{table}[h]
\centering
\begin{tabular}{@{}lll@{}}
\toprule
\code{m\%stoch\_method} & method & note \\
\midrule
\code{'heuristic'} & GD look-ahead T-window narrowing & \textbf{default}; fastest, serial \\
\code{'draine'}    & Guhathakurta \& Draine (1989) & reference GD \\
\code{'qm'}        & energy-space transition matrix (thermal-discrete) & most detailed \\
\code{'equil'}     & single-grain equilibrium (no stochastic) & see \S\ref{sec:eqtemp} \\
\bottomrule
\end{tabular}
\caption{Stochastic-heating solver options. The first three resolve the grain
temperature \emph{distribution} (PAH/NIR features); \code{'equil'} forces
equilibrium.}
\label{tab:solver}
\end{table}

\paragraph{The cooling kernel of \code{'qm'} (\code{qm\_method}).}
\code{'qm'} names the energy-space transition matrix; \emph{which}
downward-transition rate fills it is a second and independent selector, the
module variable \code{qm\_method} of \code{stoch\_qm\_mod}
(\code{use stoch\_qm\_mod, only: qm\_method}), set once before the solve. It is
module state, not a field of \code{m}, and the other three solvers never read
it.

\begin{center}
\begin{tabular}{@{}lL{0.68\textwidth}@{}}
\toprule
\code{qm\_method} & downward transition rate \\
\midrule
\code{'dbdis'} & thermal-discrete: every transition $f < i$ retained.
  \textbf{Default}, and the production reference. \\
\code{'dbcon'} & thermal-continuous: the downward rates are collapsed onto the
  nearest-neighbor transition, which reproduces the continuous-cooling
  approximation of the Guhathakurta \& Draine temperature-space recursion. \\
\code{'stati'} & exact-statistical (microcanonical): the rate carries the
  degeneracy ratio $g_f/g_i$ in place of a Planck factor, with $g(U)$ counted
  exactly by the Beyer--Swinehart algorithm over the vibrational mode spectrum,
  and the emission is the degeneracy-weighted kernel rather than a bin
  blackbody. No bin temperature enters it at all. \\
\bottomrule
\end{tabular}
\end{center}

\code{'stati'} needs the full mode spectrum and a state count that stays
representable, so it is applied only to PAH grains with $a \le 25$\,\AA\ and
reverts to \code{'dbdis'} for every other grain --- silicate included, as in
Draine's own production, whose silicate \code{'stati'} branch is flagged
untested. For a silicate grain the counted $\ln g$ that survives the
feasibility guards still carries a residual non-monotonicity of order $14$ in
the log, which the $\exp(\ln g_k - \ln g_j)$ ratio amplifies into a spurious
mid-infrared spike. Where it does run, \code{'stati'} agrees with
\code{'dbdis'} to within a few percent in every band. An unrecognized
\code{qm\_method} stops the run rather than being defaulted.

\paragraph{Sizing the transition matrix.} Two further module variables of
\code{stoch\_qm\_mod} set its dimensions, and again only \code{'qm'} reads
them: \code{qm\_nstate\_default}, the number of enthalpy bins (default
\code{200}), and \code{qm\_nisrf\_max}, the cap on how many radiation-field
wavelengths the matrix is built on (default \code{200}). Draine's production
settings are $500$ bins and the full $2500$-point field, with no downsampling.
The CLI drivers expose the kernel and both sizes as \code{qm\_dbcon} /
\code{qm\_stati}, \code{nstate=N} and \code{nisrf=N}
(\S\ref{sec:standalone:options}).

\subsection{Equilibrium-temperature options}\label{sec:eqtemp}

Two options replace the full stochastic solve when an equilibrium approximation
is wanted:

\paragraph{(1) Equilibrium temperature for each grain type and size.}
Set \code{m\%stoch\_method = 'equil'} and call \code{dust\_emission}. Every grain
is placed at its own equilibrium temperature \Teq, computed from \emph{that
grain's} absorption cross section, and emits $C_{\rm abs}\,B_\lambda(\Teq)$. No
stochastic excursions are computed.

\paragraph{(2) A single equilibrium temperature for the whole model.}
\begin{lstlisting}
call dust_emission_single_teq(m, J_lam, lamI_total [, Teq_out])
\end{lstlisting}
All dust shares one temperature, found from the type- and size-integrated
(\,dn-weighted\,) total absorption cross section
$C_{\rm abs}^{\rm tot}(\lambda) = \sum_{\rm pop}\sum_a {\rm d}n(a)\,C_{\rm abs}(\lambda,a)$.
The single \Teq\ satisfies $\int C_{\rm abs}^{\rm tot}\,J\,{\rm d}\lambda =
\int C_{\rm abs}^{\rm tot}\,B(\Teq)\,{\rm d}\lambda$, and the emission is
$C_{\rm abs}^{\rm tot}\,B_\lambda(\Teq)$. The optional \code{Teq\_out} returns that
temperature.

Both options conserve energy (the emitted bolometric power equals the absorbed
power); they differ from the stochastic solve only in the SED \emph{shape} ---
a smooth modified blackbody rather than one carrying PAH/NIR features.

\subsection{Precomputed table + interpolation}

When the field in each cell is a fixed spectral \emph{shape} scaled by an intensity
$U$, precompute a table once and interpolate per cell:
\begin{lstlisting}
type(dust_emis_table_t) :: tab
call dust_build_table(m, J_ref, U_grid, tab [, status])            ! once
call dust_emission_interp(tab, U, lamI_total [, lamI_chan] [, status])  ! per cell
\end{lstlisting}
\code{J\_ref(m\%NLAM)} is the reference field shape (at $U{=}1$) and
\code{U\_grid(:)} an ascending intensity grid. The table is built from exact
solves, so it is exact at the grid points; interpolation is log--log in $U$.
The stored emissivities are floored at $10^{-300}$ before the log, so a grid
node whose true value is $0$ comes back as $10^{-300}$ rather than exactly $0$.
Both calls take an optional final \code{status} (\S\ref{sec:status}).

\paragraph{Caveat.} Stochastic emission is a \emph{nonlinear} functional of the
full $J(\lambda)$, not of a scalar. The table is valid only when the cell field
is $U\times(\text{fixed }J_{\rm ref})$. For cells whose field \emph{shape}
departs from $J_{\rm ref}$ (e.g.\ hardened spectra near hot stars), use the
cell-by-cell exact \code{dust\_emission}.

\subsection{Optional error status}\label{sec:status}

The builders and the emission/table calls each accept an optional final
\code{status} argument (\code{integer, intent(out)}). When it is present, an
invalid model, argument, or input file is reported through it (\code{status = 0}
on success, nonzero on failure) and the process keeps running, so a 3D RT host
can recover; when it is omitted, the same condition prints a message and
\code{stop}s the run, which the CLI drivers rely on. For the builders the
nonzero value only names the failing stage: the contract is simply
\code{0} = built, nonzero = build failed.

\code{build\_dust} carries a vocabulary of its own, and maps each builder's
stage number onto it, so a host on the single entry point never branches on the
model name to read a code. It also takes an optional \code{message}
(\code{character, intent(out)}) carrying the reason in words, which is what an
MPI host prints before a collective abort:

\section{Computing extinction}\label{sec:ext}

\code{dust\_extinction} is the extinction counterpart of \code{dust\_emission}:
a transfer code takes its opacity from the same model object, and on the same
wavelength grid \code{m\%lam}, as its emission.

\begin{lstlisting}
call dust_extinction(m, Cext, Cabs, Csca [, gbar] [, albedo] [, status])
\end{lstlisting}
\begin{itemize}
\item \code{Cext}, \code{Cabs}, \code{Csca} \code{(m\%NLAM)}: extinction,
      absorption and scattering cross sections per H atom [\,cm$^2$/H\,], with
      $C_{\rm ext} = C_{\rm abs} + C_{\rm sca}$.
\item \code{gbar(m\%NLAM)} (optional): the scattering-weighted asymmetry
      $\langle\cos\theta\rangle$ as the table carries it, which is $0$ where
      nothing scatters and may be slightly negative in the far infrared.
\item \code{albedo(m\%NLAM)} (optional): $C_{\rm sca}/C_{\rm ext}$, and $0$
      where $C_{\rm ext}$ underflows to zero. It is derived here rather than by
      the caller so that every host gets the same convention at those
      wavelengths.
\item \code{status} (optional): error report; see \S\ref{sec:status}.
      It is $0$ on success, $1$ if an output array is not of size
      \code{m\%NLAM}, $2$ if no extinction table was loaded for this model, and
      $3$ if \code{m\%lam} reaches outside the table.
\end{itemize}

\subsection{What the call returns, and where it comes from}

\code{dust\_extinction} \emph{reads} the size-integrated curve from the
precomputed table its builder loaded (\code{m\%kext\_path}; see the
\code{kext\_path} argument in \S\ref{sec:models} and
Table~\ref{tab:models:kext}).
Nothing is integrated over grain size at call time. The size integral itself is
the separate routine \code{size\_integrated\_extinction}, which has the same
argument list, is what \code{calc\_kext.x} calls, and is what wrote those
tables:
\begin{align*}
C_{\rm abs}(\lambda) &= \sum_{\rm pop}\sum_a {\rm d}n(a)\,C_{\rm abs}(\lambda,a), \\
C_{\rm sca}(\lambda) &= \sum_{\rm pop}\sum_a {\rm d}n(a)\,C_{\rm sca}(\lambda,a), \\
\langle\cos\theta\rangle &= \frac{\sum {\rm d}n\,C_{\rm sca}\,g}{\sum {\rm d}n\,C_{\rm sca}},
\end{align*}
a plain binned sum over every population, since ${\rm d}n(a)$ already carries
the bin width. It is exported too, for a host that would rather redo the
integral than read the product; \code{dust\_extinction} is the route that gives
an RT host exactly the numbers that were checked against the HD23 release and
Draine's own \code{kext\_albedo} tables (\S\ref{sec:euv-refs}).

\paragraph{Why the builder holds the table.} The table paths are relative to
\code{sed/}, and a host typically changes directory back as soon as the model is
built --- so the file has to be opened while the builder still runs, not when
\code{dust\_extinction} is called. That is the whole reason \code{kext\_path} is
a builder argument.

\paragraph{Interpolation onto \code{m\%lam}.} Needed only where the table grid
and the model grid differ. $C_{\rm ext}$, $C_{\rm abs}$ and $C_{\rm sca}$ are
positive and locally power-law in $\lambda$, so they are interpolated linearly
in $(\ln\lambda,\ln C)$; $\langle\cos\theta\rangle$ changes sign and has no
logarithm, so it is linear in $\ln\lambda$. Where a model wavelength
\emph{coincides} with a table wavelength the table value is returned unchanged,
which is the normal case for the shipped defaults --- the EUV table's nodes are
the plain grid's nodes over the overlap. Outside the tabulated range there is no
optics to serve, so the call is refused (\code{status = 3}) rather than
extrapolated.

\paragraph{Two quantities are not read straight from the file.}
\code{albedo} is re-derived as $C_{\rm sca}/C_{\rm ext}$ from the interpolated
cross sections instead of from the file's own albedo column, because the cross
sections are written with more digits (the oldest product rounds its albedo
column to six decimals, which floors to $0$ in the far infrared).
\code{gbar} \emph{is} taken from the table as it stands: it is already the
scattering-weighted average, and re-weighting it would need the size-resolved
optics the table does not carry.

\paragraph{Every model scatters.} Every builder populates the
extinction-side scattering optics, so the \code{albedo} and \code{gbar} in every
table are physical:

\begin{itemize}
\item \textbf{astrodust}: $C_{\rm sca}$ and $\langle\cos\theta\rangle$ from the
      random-orientation T-matrix $Q$ table, at every wavelength of the model.
\item \textbf{DL07}: Mie on the D03 astrosilicate and graphite dielectric
      functions (\code{q\_silicate\_full} / \code{q\_graphite\_full}), on the
      same random-orientation average ($\tfrac13\,E\!\parallel\!c +
      \tfrac23\,E\!\perp\!c$) as the absorption. The two carbonaceous charge
      states share one scattering description: charge shifts PAH absorption
      features, not the graphite sphere's scattering.
\item \textbf{MRN}: the same two calculations, on this model's own 70-point
      radius grid.
\item \textbf{Zubko / file-defined}: the $Q_{\rm sca}$ and $g$ columns of the
      model's own ZDA optics tables, read from the same file as $Q_{\rm abs}$.
      Those tables are a \emph{homogeneous-sphere} Mie calculation --- Zubko
      et al.\ (2004, \S3) state it for the bare grains, and each file's header
      names the dielectric function it came from, Draine's \code{eps\_Sil} and
      \code{eps\_Gra}; the effective-medium step of that paper applies to its
      composite models, not to BARE-GR-S. The PAH file is not Mie at all: its
      header names the Li \& Draine (2001) / Draine \& Li (2007) absorption
      cross sections. \S\ref{sec:zubko-mie} records what recomputing the
      silicate table with our own Mie gives.
\end{itemize}

\noindent A population that genuinely does not scatter leaves its scattering
optics unallocated and contributes zero. No population of any shipped model is
that case. The PAHs come closest, since a PAH has a published absorption cross
section and no scattering one, but what scatters in a PAH population is its
graphite fraction $\xi_{\rm gra}(a)$ of HD23 equation~(15), and the model
carries it: dropping it costs $3.2\%$ of $\tau_{\rm sca}$ at $0.1\,\mu$m
against the HD23 release and nothing longward of $0.3\,\mu$m.

\subsection{Dust mass per H, and mass opacity}\label{sec:mass}

Everything above is \emph{per H nucleon}. A host that carries a dust mass
density instead needs the model's own dust mass per H to convert:

\begin{lstlisting}
Mdust_H = dust_mass_per_H(m)     ! [g/H], one wavelength-independent constant
Kabs    = Cabs / Mdust_H         ! [cm^2/g], Draine's mass opacity
\end{lstlisting}

\noindent It is the model's own size distribution weighted by the solid density
of each population's material,
\[
  \frac{M_{\rm dust}}{N_{\rm H}}
   = \sum_{\rm pop}\rho_{\rm bulk}\sum_a \tfrac43\pi a^3\,{\rm d}n(a),
\]
with $a$ the effective radius in cm and ${\rm d}n(a)$ the same binned number per
H the size integral above uses, so no ${\rm d}a$ enters the sum. The density
lives on the population (\code{m\%pops(ip)\%rho\_bulk}, \S\ref{sec:model});
a population whose model states none leaves it at $0$ and contributes no mass.
The function reads \code{m} only --- it needs no radiation field and no built
optics beyond the model itself.

Every builder states its densities, so the quantity is defined for every model
in the tree:

\begin{center}
\small
\begin{tabular}{@{}llr@{}}
\toprule
model & grain densities [g/cm$^3$] & $M_{\rm dust}/N_{\rm H}$ [g/H] \\
\midrule
astrodust & astrodust $2.74$, PAH $2.0$ (HD23)            & $1.185\times10^{-26}$ \\
DL07      & astrosilicate $3.5$, graphite $2.2$           & $1.750\times10^{-26}$ \\
MRN       & astrosilicate $3.5$, graphite $2.2$           & $1.525\times10^{-26}$ \\
Zubko     & each component's own ZDA optics header ($3.5$, $2.24$, $2.24$) & $1.444\times10^{-26}$ \\
file-defined & the \code{pop:} line's \code{rho}, else the optics file's & --- \\
\bottomrule
\end{tabular}
\end{center}

\noindent The astrodust numbers are Hensley \& Draine (2023): $\rho_{\rm Ad} =
2.74$ is the porosity-corrected solid density of the astrodust material, and
$\rho_{\rm PAH} = 2.0$ is the density behind that model's $N_{\rm C} = 417\,
(a/{\rm nm})^3$. The DL07 numbers are stated by that model's own paper, Draine
\& Li (2007) \S2, in the paragraph defining the effective radius $a = (3M/4\pi
\rho)^{1/3}$: amorphous silicate $3.5$ (also the density the DL01
astrosilicate enthalpy is built on), and carbonaceous grains ``a mass density
due to graphitic carbon alone of $\rho = 2.2$ g cm$^{-3}$''. That is
deliberately \emph{not} the $2.24$ of WD01 and LD01, which is the density
implied by the carbon-atom count $N_{\rm C} = 470\,(a/{\rm nm})^3$ the DL07
builder selects; DL07 kept that count and quoted the rounder density, and the
model being built here is DL07's. The DL07 carbonaceous grains are one material
sequence, PAH-like at small $a$ and graphite-like at large $a$ with no size at
which the solid changes, so the one density is used across the whole sequence.
That the astrodust PAHs take $2.0$ and the DL07 carbonaceous grains $2.2$ is a
difference between the two \emph{models}, not a correction of one by the other.
The Zubko densities are read out of the \code{Density} entry in the header of
each component's own ZDA optics table.

\paragraph{Check against DL07, and a caution about his data files.} Table 3 of
Draine \& Li (2007) lists $M_{\rm dust}/M_{\rm H}$ for each of its physical dust
models. Model $j_M = 7$, \code{MW3.1\_60}, is the size distribution this builder
selects, and the paper gives $0.0104$. Ours is $1.750\times10^{-26}$ g/H, i.e.\
$0.01046$ --- agreement to $0.55\%$.

Draine's \code{kext\_albedo\_WD\_MW\_3.1\_60\_D03.all} header, for the same
model, instead states $M_{\rm dust}/N_{\rm H} = 1.870\times10^{-26}$ g/H, which
is $M_{\rm dust}/M_{\rm H} = 0.0112$ and therefore $7.4\%$ away from his own
Table 3. The same file disagrees with the paper on the silicate normalization as
well: the header says the WD01 abundances were reduced by $0.93$, while the
caption of the paper's Fig.~11 says $0.92$.

The position taken here is to follow the \emph{file} for the optics and the
\emph{paper} for the mass. The optics are not in question --- our $C_{\rm
abs}/{\rm H}$ agrees with the 2003 table to better than $0.5\%$ from $100$ to
$10^4$\um, where absorption is in the Rayleigh limit and therefore proportional
to the grain volume, so the material volumes agree with his. What is left is the
$\sim1\%$ that the two normalizations differ by, and it is Draine's own internal
inconsistency, not ours. It is worth knowing that $K_{\rm abs}$ from any of these
tables inherits whichever convention was used: $C_{\rm abs}/{\rm H}$ is the
better-determined quantity, and $K_{\rm abs}$ is that number divided by a
convention.

\section{The extreme-ultraviolet extension}\label{sec:euv}

The astrodust model's wavelength grid is the grid of the T-matrix $Q$ table it
was built from, and \emph{two} tables ship side by side:
\begin{center}
\begin{tabular}{lrl}
\hline
file & wavelengths & range [\um] \\
\hline
\code{q\_astrodust\_P0.20\_Fe0.00\_1.400.dat}     & 1129 & $0.0912$ -- $39810$ \\
\code{q\_astrodust\_P0.20\_Fe0.00\_1.400\_euv.dat} & 1762 & $10^{-4}$ -- $39810$ \\
\hline
\end{tabular}
\end{center}
The second spans \SI{12.4}{\kilo\electronvolt} down to
\SI{0.031}{\electronvolt}; the first is that file with every wavelength
shortward of the Lyman limit dropped (\code{make lyman\_cut} in
\code{tmatrix/}), row selection only, so over the 1129 they share they are the
same numbers cell for cell. \textbf{Which one the host passes as \code{qtab}
decides what its model covers.} Given the \code{\_euv} table, the ionizing band
is inside the table, computed the same way as the rest of it, so a host that
transports ionizing radiation reads it off the table and needs nothing more ---
in particular it does not have to link \code{libtmatrix.a}. Given the default
table, a model that needs the band builds one, and \S\ref{sec:euv-shape} is
where its optics come from.

Below $0.0912$\um\ the \code{\_euv} table's wavelengths are the DH21 dielectric function's own
energy nodes rather than a resampling of them. That band is full of absorption
edges, each tabulated as a step across a close pair of energies --- the
separations run from $2.4\times10^{-6}$ to $3.6\times10^{-4}$ in relative
energy, and $k$ jumps by $+211\%$ at Fe\,K (\SI{7124}{\electronvolt}), $+131\%$
at O\,K (538), $+67\%$ at Fe\,L (724), $+30\%$ at C\,K (291), $+27\%$ at Si\,K
(1846) and $+26\%$ at Mg\,K (1311). Counting them takes a threshold, and the
answer moves with it: 23 places where $k$ jumps by more than $0.5\%$ across a
pair closer than $5\times10^{-4}$, of which 14 are closer than $10^{-4}$. A
uniform 200-per-decade axis would average every one of them into a ramp.
Reusing the nodes
keeps every edge an exact step between adjacent grid points, and makes the
refractive index at each point the tabulated one rather than an interpolate.

One point is deliberately not a dielectric node: $0.0912\,(1-10^{-4})$, just
below the Lyman limit. It is placed for the \emph{radiation field}, not for the
grain --- see \S\ref{sec:euv-lyman}.

Both \code{build\_astrodust} and \code{build\_dl07} take an optional
\code{lam\_min} [\um] for a host that needs to reach below the table it was
given:
\begin{lstlisting}
call build_dl07(m, qtab, NT, T_lo, T_hi, lam_min=6.21e-5_wp)
\end{lstlisting}
Log-spaced points are then prepended from \code{lam\_min} up to the table, at a
step no coarser than the table's own $\Delta\ln\lambda$ at its short-wavelength
end ($0.00794$ on the \code{\_euv} axis, $0.01156$ on the other), with
\code{m\%lam(1)} set to \code{lam\_min} exactly. The
request is refused (\code{status = 4}) when it asks for a wavelength the model's
own dielectric data does not cover, rather than served with a refractive index
frozen at the table boundary. \textbf{Omitting \code{lam\_min}, or passing one
the table already covers, prepends nothing.}

What \code{lam\_min} does for astrodust therefore depends on which table the
model was built from. On the default 1129-wavelength table a \code{lam\_min}
below $0.0912$\um\ builds a band. On the \code{\_euv} table there is nothing
left to ask for: it already reaches the short-wavelength end of the DH21
dielectric function, so every \code{lam\_min} either falls inside the table (no
band) or below the dielectric data (refused). DL07 and MRN can be extended below
either, to $6.205\times10^{-5}$\um, because the D03 optical constants their
optics come from reach further than both.

\subsection{A step in the field needs a grid point, exactly as a step in the
material does}\label{sec:euv-lyman}

An interstellar radiation field is exactly zero below the Lyman limit and finite
above it: \code{J\_Mathis} in \code{sed/src/radfield.f90} opens with
\code{if (lambda(i) < 0.0912d0) J(i) = 0}, and immediately above the limit
$J_\lambda = 3069\,\lambda^{3.4172}$ is $0.856$. That is a step discontinuity of
the \emph{field}.

The DH21 dielectric energy axis has no node between $13.595$ and
\SI{14.000}{\electronvolt}. Built from those nodes alone, the grid would jump
from $0.088557$\um\ straight to $0.0912$\um\ --- one cell $2.98\%$ wide, sitting
across the step. Every wavelength integral in the library is a trapezoid sum, so
that cell would integrate a ramp rising from zero and count absorption in a band
where the field carries no photon at all. Measured on the shipped optics, with
$C_{\rm abs}$ from the $Q$ table itself, it inflates the absorbed power of the
smallest grains by $1.74\%$ (falling to $0.05\%$ for $a\ge0.3$\um, which take
little of their heating in the ultraviolet). Small grains are the ones the
stochastic solver treats, so the error does not stay small: it moved the
equilibrium/stochastic boundary by twenty radii and shifted the emergent SED by
up to $13\%$ at the far-infrared peak.

The extra grid point at $0.0912\,(1-10^{-4}) = 9.119088\times10^{-2}$\um\ closes
that cell, and with it the artifact: $1.74\% \to 0.006\%$. Its refractive index
is interpolated rather than tabulated, which costs nothing --- the astrodust
dielectric function is smooth across \SI{13.6}{\electronvolt} and has no edge
there. The Lyman limit is a property of the illumination, and this is the same
move the extension already makes at every one of the material's own edges:
resolve a step with a close pair of points.

\subsection{Where the optics come from in the extended band}

\begin{itemize}
\item \textbf{Astrodust grains.} The T-matrix on the Draine \& Hensley (2021)
      dielectric function --- the same material \emph{and} the same $b/a =
      1.400$ oblate spheroid as the $Q$ table, on the same random-orientation
      average, so the band continues the table's own calculation instead of
      substituting a different particle for it. This is the default; passing
      \code{euv\_tmatrix=.false.} instead selects Bohren--Huffman Mie for the
      \emph{volume-equivalent sphere}, much cheaper but an approximation.
      Both are described in \S\ref{sec:euv-shape}. On the \code{\_euv} table
      \textbf{neither is ever reached}, because no astrodust band forms below
      it and the flag has no effect; on the default 1129-wavelength table a
      \code{lam\_min} below the Lyman limit reaches them.
\item \textbf{PAH / carbonaceous.} Above \SI{21.4}{\electronvolt}
      ($1/\lambda = 17.25\ \mu\mathrm{m}^{-1}$) the DL07 PAH cross section is
      zero by construction, so graphite is the \emph{whole} carbonaceous
      absorption there. Below that energy the D16 turbostratic-graphite sphere
      table is used as before; above it the code switches to Mie on the D03
      graphite dielectric functions (random orientation, $\tfrac13$ parallel
      $+\,\tfrac23$ perpendicular), because the D16 table's radius axis bottoms
      out at $10^{-3}$\um\ while the astrodust size grid starts at
      $3.55\times10^{-4}$\um. In the Rayleigh limit $Q_{\rm abs}\propto a$, so
      clamping a smaller grain to the table's first radius overestimates its
      absorption by $10^{-3}\,\mu\mathrm{m}/a$ --- up to $2.4\times$ for the
      smallest PAH the size distribution populates ($4.22\times10^{-4}$\um).
      \emph{This branch is unreachable on the unextended grid}: its shortest
      wavelength gives $1/\lambda = 10.96 < 17.25$, so every previous result is
      unaffected.
\item \textbf{DL07 model.} Its optics are Mie on the D03 dielectric functions at
      \emph{every} wavelength, so nothing changes character across the band and
      the extension is a grid extension only.
\item \textbf{Zubko model.} No extension, and none possible: its tabulated
      optics already span $10^{-3}$ to $10^{4}$\um, and those tables \emph{are}
      the model definition, so there is no dielectric function to extend them
      with.
\end{itemize}

\subsection{The two routes, and what the cheap one costs}\label{sec:euv-shape}

\emph{Read this section as a description of a route that no longer has anything
to compute for astrodust.} It was written when the $Q$ table stopped at the Lyman
limit and every ionizing host needed a band solved on the fly. The table now
covers that band, so the astrodust EUV path is unreachable --- which is the
point: no host has to link the T-matrix any more. The route is kept because it
is what would compute a band if a future dielectric function reached further
than the table built from it, and because the timings below are the measurement
that justified moving the work into the table. In particular \textbf{the
volume-equivalent-sphere substitution described here is used nowhere in the
shipped astrodust products}: every wavelength of every one of them is read off
the $Q$ table, and no argument to \code{build\_astrodust} can change that.

The $Q$ table is a random-orientation T-matrix solution for an oblate spheroid
of axial ratio $b/a = 1.4$. \textbf{By default the extended band is the same
solution}, called directly (\code{spheroid\_q} in
\code{tmatrix/driver/spheroid\_optics.f90}) on the same dielectric function,
with the same convergence tolerance and the same regime bounds the table's own
driver uses: the Rayleigh dipole limit below $x = 2\pi a_{\rm eff}/\lambda =
0.1$, the T-matrix between $0.1$ and $50$, the geometric-optics limit above
$50$. Nothing about the particle changes across the seam.

That solution lives in \code{sed/src/euv\_astrodust\_tmatrix.f90}, the one file
of the library that reaches into \code{libtmatrix.a}, and it is reached through
a registered procedure rather than a compiled dependency --- which is what lets
the rest of the library link without the T-matrix at all
(\S\ref{sec:build}). A build that does not carry it answers
\code{euv\_tmatrix = .true.} with \code{status = 6}; it never falls back to the
sphere below, because that is a different particle and the caller has to know.

That is not free. Measured on this machine (\code{gfortran}~13.1, \code{-O3},
167 radii; the timings are the band alone, as \code{sed\_init} reports them):

The band is built with OpenMP over grain radii, with one T-matrix workspace for
each thread (37\,MiB at allocation, 80\,MiB once its full-direct arrays are in
place; nothing is allocated when there is no band to compute). That is the one
thing to watch on a many-core host: peak resident memory measured
64\,MB / 110\,MB / 197\,MB / 376\,MB at 1 / 2 / 4 / 8 threads and 3.0\,GB at 72,
so cap \code{OMP\_NUM\_THREADS} if memory is tight. Each radius writes its own
column and reads no other, so the result does not depend on the thread count or
the schedule --- the four runs above wrote byte-identical optics.

\paragraph{The cheap route.} \code{euv\_tmatrix=.false.} replaces the spheroid
by its volume-equivalent \emph{sphere} and solves it with Bohren--Huffman Mie,
in a tenth of a second. The justification for that substitution is \textbf{not}
the anomalous-diffraction argument $|m-1|\ll1$: for this material $|m-1| = 0.77$
at the seam and still $0.56$ at \SI{20}{\electronvolt}. It rests instead on the
two limits that actually apply:

\begin{itemize}
\item \textbf{Small grains are in the Rayleigh limit} ($x = 2\pi a/\lambda =
      0.033$ at the seam for the smallest populated radius, and only $0.24$ at
      \SI{100}{\electronvolt}). There the ellipsoid polarizability is
      $\alpha_j = V(\epsilon-1)/\{4\pi[1 + L_j(\epsilon-1)]\}$, so shape enters
      \emph{only} through $L_j(\epsilon-1)$. And $|\epsilon-1|$ falls from
      $1.86$ at \SI{13.5}{\electronvolt} to $1.10$ at \SI{20}{\electronvolt},
      $0.28$ at \SI{40}{\electronvolt} and $0.061$ at
      \SI{100}{\electronvolt}: the depolarization factors drop out and sphere
      and spheroid converge on the same $C_{\rm abs}$.
\item \textbf{Large grains are in the geometric-optics limit}, where $C_{\rm
      ext}\to2\times$(orientation-averaged projected area). By Cauchy's theorem
      that average is $S/4$, and for $b/a = 1.4$ the spheroid's $S/4$ exceeds
      $\pi a_{\rm eff}^2$ of its volume-equivalent sphere by 2.12\%. Mie is
      therefore low by $1 - 1/1.0212 = 2.08\%$ in that limit. \textbf{The error
      converges to a constant, not to zero}, however far into the EUV one goes.
\end{itemize}

\noindent Consequently the error does \emph{not} fall monotonically with photon
energy. Only $a\lesssim2\times10^{-3}$\um\ improves monotonically; $a\gtrsim
0.01$\um\ gets \emph{worse} between 13.6 and \SI{30}{\electronvolt} before
recovering, and the largest sizes settle at a nearly energy-independent
$-1.9$ to $-2.0\%$. Over the whole band and the whole size range the error stays
within about 2\%; \code{sed/src/q\_astrodust.f90} tabulates it size by size.

\subsection{The single-photon ceiling comes from the field}\label{sec:euv-ceiling}

The stochastic solvers set the top of a grain's enthalpy window from the energy
of the hardest single photon it can absorb. That ceiling used to be the
hard-coded Lyman limit, $13.6\,$eV, which an ionizing band makes wrong: a photon
harder than the ceiling drives an excursion the window cannot hold. It is now
\begin{center}
$\max\!\left(13.6\,\mathrm{eV},\ hc/\lambda_{\rm hard}\right)$, \qquad
$\lambda_{\rm hard} = \min\left\{\lambda_i\ :\ J_\lambda(\lambda_i) >
10^{-12}\,\max_j J_\lambda(\lambda_j)\right\}$,
\end{center}
computed by \code{hardest\_photon\_energy} in \code{sed/src/radfield.f90} and
called from all four places that need it --- \code{sed\_grain\_loop} and
\code{narrow\_iterative} in \code{sed\_astrodust.f90}, \code{qm\_solve\_grain}
in \code{stoch\_qm.f90}, and \code{calc\_P} in \code{p\_sub.f90}. Any units may
be passed for $J_\lambda$, since only ratios within the array are used.

\code{calc\_P} is the fourth because it does not merely bound a window: it
integrates the upward transition rates over the photons that drive them, so both
the cutoff and the limits of that integral are properties of the field.
\S\ref{sec:euv-ghost} is what it cost to have taken them from the grid instead.

\paragraph{The ceiling is a property of the field, not of the grid.} That
distinction is the whole point, and a coincidence hides it. A model's wavelength
grid is the grid of its optics tables, which can reach far past the band a
transported field occupies:

\begin{center}
\begin{tabular}{@{}lll@{}}
\toprule
model & grid floor & implied photon energy \\
\midrule
astrodust & $1.000\times10^{-4}$\um\ (T-matrix $Q$ table) & $12398\,$eV \\
DL07      & $1.000\times10^{-4}$\um\ (the same table)     & $12398\,$eV \\
MRN       & $1.000\times10^{-4}$\um\ (the same table)     & $12398\,$eV \\
Zubko     & $1.000\times10^{-3}$\um\ (ZDA optics tables)      & $1239.8\,$eV \\
\bottomrule
\end{tabular}
\end{center}

\noindent Every shipped model now depends on the distinction: the grid floors
above sit $912$, $912$ and $91$ times harder than a Mathis field's own, which is
the Lyman limit, and the field is the one that is right --- it carries no photon
at all below $0.0912$\um, however far the optics table extends. Before the $Q$
table was carried into the ionizing band, astrodust and DL07 could not tell the
two apart: their grid floor \emph{was} the Lyman limit
($13.595\,\mathrm{eV} < 13.6\,\mathrm{eV}$, so the maximum returned the constant
whichever was measured), and Zubko was the only model that exercised the
difference.

\paragraph{Taking it from the grid costs resolution, not physics.}
\code{umax} sets the upper edge of a \emph{fixed} number of enthalpy bins, so a
ceiling 91 times too high starts the solve with bins 91 times too coarse. The
refinement loops do contract the window once the top bin is unpopulated, but the
contraction is guarded (\code{umax > 1.02*umaxlo} and
\code{umax > 1.01*ub(jcut)}) and capped at \code{MAX\_ITER = 10}, so it does not
return to where it began; expansion carries no such guard. Measured in a host
code on the Zubko model, with no \code{lam\_min} requested at all: dust
temperature $+0.0705\,$K median and positive in every cell, the ten brightest
SED bins $-0.9$ to $-1.9\%$, the emission image $1.9\%$ median and $5.4\%$
maximum, total emitted energy $-0.08\%$. A systematic redistribution at nearly
conserved energy is what a coarser bin grid produces, and
\code{docs/EUV\_EXTENSION\_HOST\_REGRESSION.md} records the measurement.

\subsection{The photon that was not there}\label{sec:euv-ghost}

The ceiling above bounds a \emph{window}. \code{calc\_P} does something
stronger: it integrates the upward transition rates over the photons that drive
them. Until this release it took the limits of that integral from the grid, and
the result was not a loss of resolution but a source of energy that does not
exist.

The highest-bin term is the rate into the top enthalpy bin, driven by every
photon more energetic than that bin's gap $\Delta H$. Two things went wrong.

\begin{itemize}
\item \textbf{The integral started at \code{lambda(1)}}, the short end of the
      optics table, rather than at the shortest wavelength the field occupies.
      On the grid ending at the Lyman limit the two coincided; carried to
      $10^{-4}$\um\ they differ by $912$, and a flat 51-point rule left between
      1 and 8 samples inside the illuminated band.
\item \textbf{The flux at the gap wavelength was read through a clamping
      interpolator.} \code{interp1} returns $y(1)$ for any abscissa below its
      range. The top bin is placed above the single-photon bound by
      construction, so $hc/\Delta H$ was always shorter than the grid, and the
      clamp answered every time with $J_\lambda$ at the grid edge instead of
      zero --- on a grid ending at the Lyman limit, the full Mathis intensity
      there. \emph{Every top-bin transition was driven by a photon flux the
      field does not carry.} When $\Delta H$ exceeded the grid's whole range the
      same clamp made the loop run backwards, subtracting a rate rather than
      adding none.
\end{itemize}

Both limits now come from \code{hardest\_photon\_energy}, and the band is
skipped when $\Delta H$ exceeds the hardest photon. The sample count follows the
band's width (\code{NWAV\_MIN}, \code{NWAV\_MAX}, \code{DLNWAV\_TARGET} in
\code{p\_sub.f90}) instead of being fixed, so the step is bounded whatever the
band. Re-running the old grid with only the ghost removed and then only the
sampling changed separates the two: the sampling moves nothing at all
($0.0000\%$), which says the flat 51 points had already converged once the
limits were right; the ghost carries the entire change.

\textbf{All three models shipped at the time moved}, and Zubko's move has nothing to do with
the astrodust table --- its grid has always begun at $10^{-3}$\um, so it carried
the same defect independently. Against the previous products: astrodust up to
$12.1\%$ locally and $-1.1$ to $+0.9\%$ in integrated power, DL07 $9.7\%$ and
$-2.8\%$, Zubko $3.0\%$ ($6.0\%$ with \code{euv}). Energy conservation, measured
as emitted over absorbed power per H, improved from $+0.236\%$ to $-0.057\%$ for
the astrodust S1 stage and held at $-0.11\%$ for S2.

\medskip
\noindent\textbf{Every SED this package produced before this fix contains
photons that were not in the field}, in the top enthalpy bin of every
stochastically heated grain. Comparisons against those products have to account
for it.

\paragraph{Why $10^{-12}$ of the peak, and not simply $J_\lambda>0$.} Exact
zeros must be excluded --- \code{J\_Mathis} returns exactly zero below
$0.0912$\um\ --- but an exact positivity test is too fragile: a host that hands
over denormal or roundoff-level residue in its unilluminated bins would push the
ceiling back up by orders of magnitude. A component a fraction $10^{-12}$ below
the peak of $J_\lambda$ contributes at most that fraction of the photon
absorption rate; allowing two decades for the run of $C_{\rm abs}$ across the
illuminated band, the enthalpy states it could populate carry probability
$\lesssim10^{-10}$ of the peak, at or below the $10^{-13}$ tail level
(\code{PMIN\_UP}, \code{PMIN\_UP\_QM}) at which both solvers already truncate
the window. Such a component cannot change a resolved excursion, and $10^{-12}$
still sits eighteen decades above the residue it is meant to reject.

\medskip
\noindent The error is one-sided on purpose. Both refinement loops \emph{expand} the
window while the top bin is still populated, so an underestimated ceiling is
corrected as the loop runs; the guarded contraction can stop short of where it
began, so an overestimate is not corrected at all. \code{MAX\_ITER = 10} bounds
the correction in either direction. Overestimating is therefore the dangerous
direction, which is why the threshold is set high enough to reject junk rather
than as low as floating point allows.

\paragraph{\code{calc\_sed.x zubko} exists to keep this path covered.} The defect
escaped \code{calc\_sed.x astrodust} and \code{calc\_sed.x dl07} because for those two
models the grid floor and the field's short end are the same number: no driver
in the tree ran the emission solvers on a model whose optics grid reaches past
the illuminated band. \code{calc\_sed.x zubko} (\S\ref{sec:standalone:zubko}) closes
that gap and is built by the default \code{make}. It prints the two candidates
side by side, so the difference shows in the first lines of output:
\begin{lstlisting}[style=sh]
$ ./calc_sed.x zubko                 # grid cut at the Lyman limit, Mathis field
 optics grid short end :  8.9984E-02 um  ->   1.37784E+01 eV
 hardest photon in the field:    1.35946E+01 eV
 single-photon bound in use :    1.36000E+01 eV
$ ./calc_sed.x zubko euv             # whole ZDA grid, still the Mathis field
 optics grid short end :  1.0000E-03 um  ->   1.23984E+03 eV
 hardest photon in the field:    1.35946E+01 eV
 single-photon bound in use :    1.36000E+01 eV
$ ./calc_sed.x zubko euv hardfield   # ... and a hard component added to the FIELD
 optics grid short end :  1.0000E-03 um  ->   1.23984E+03 eV
 hardest photon in the field:    3.70141E+02 eV
 single-photon bound in use :    3.70141E+02 eV
\end{lstlisting}
The middle run is the one that matters: the optics grid reaches
\SI{1.24}{\kilo\electronvolt} and the ceiling must still stay at $13.6\,$eV,
because the field stops there. Only \code{hardfield}, which puts photons in that
band, may move it --- and it does, to the same $370\,$eV the field itself
carries. \code{hardfield} implies \code{euv} for that reason: on the cut grid
there is no wavelength to put those photons on.

\paragraph{A model built without \code{lam\_min} is unaffected.} For astrodust
and DL07 the maximum selects the $13.6\,$eV constant on the unextended grid
either way, so those results are unchanged to the last bit.

\subsection{What else the extension does, and does not, change}

\begin{itemize}
\item \textbf{The Planck integrals are anchored to the table range.} The
      internal log-$\lambda$ integration grid for $\kappa_B(T,a)$ keeps its step
      and its sample points over the optics-table range and merely
      \emph{prepends} points below it, so widening the model grid cannot
      coarsen the sampling of the range that carries the integrand. Measured:
      with a $1.001\times10^{-4}$\um\ floor, $\kappa_B$ is unchanged to
      round-off over the thermal range ($\max|\Delta\kappa_B|/\kappa_B =
      3.4\times10^{-16}$ for $T\le\SI{3000}{\kelvin}$, and exactly zero below
      $\sim\SI{2400}{\kelvin}$); $\kappa_{\rm CMB}$ is bit-identical. The only
      nonzero difference is $1.1\times10^{-8}$ at the very top of a
      \SI{5000}{\kelvin} grid, where the Wien tail genuinely reaches into the
      extended band --- that is real extra emission, not a sampling artifact.
      Without the anchoring, spending a fixed budget of points on the widened
      interval would have moved $\kappa_B$ by $\sim10^{-4}$ for a purely
      numerical reason.
\item \textbf{Stochastic heating by hard photons is not solved by this change.}
      The extension fixes the photon-energy mapping and the absorbed-energy
      accounting. It does not address the finite enthalpy grid: upward
      transitions above the top of that grid are accumulated into the highest
      temperature bin, and for the smallest PAHs a \SI{54}{\electronvolt}
      photon already exceeds $H(\SI{5000}{\kelvin})$. Nor does it add
      photoionization, electron energy loss, fragmentation or PAH destruction.
      Treat the extended band as extinction and absorbed-energy physics, not as
      a validated hard-EUV PAH \emph{emission} model.
\end{itemize}

\section{Standalone programs}\label{sec:standalone}

Every program here is named for the quantity it computes --- \code{calc\_sed.x}
for the emission SED, \code{calc\_kext.x} for the size-integrated transport
optics, \code{calc\_qtable.x} for the stored cross-section tables,
\code{calc\_enthalpy.x} for the enthalpy tables --- so that none of them can be
mistaken for the build tool. \code{make} in \code{SEDust/sed/} builds the
default set; the rest have make targets of their own. All of them are run
\emph{from} \code{SEDust/sed/}, because every data path is relative to
\code{../}.

They also share ONE command-line system (\S\ref{sec:standalone:options}): one
vocabulary, one parser, one refusal and one filename-tag rule, with each program
declaring which axes it has a referent for.

\subsection{\code{calc\_kext.x} --- size-integrated transport optics}

Builds a model and calls \code{size\_integrated\_extinction} on it, then writes
the result under \code{../data/}. Every model goes through the same two calls,
and \code{dust\_extinction} later serves these very files back to an RT host, so
the files written here \emph{are} the optics that host gets in memory.

\begin{lstlisting}[style=sh]
./calc_kext.x astrodust [euv | <lam_min in um>]
./calc_kext.x dl07 [ld01] [euv | <lam_min in um>]
./calc_kext.x mrn       [euv | <lam_min in um>]
./calc_kext.x zubko     [formula | table] [zda | mie_d03] [euv]
./calc_kext.x from_files <descriptor> [data_dir]
\end{lstlisting}

\noindent With no argument it prints its usage and stops. \code{euv} carries the
grid down to whatever the model's own dielectric function covers; an explicit
number requests a specific floor in \um. \code{zubko} defaults to
\code{formula}. \code{from\_files} takes the descriptor path, and the data
directory defaults to the descriptor's own directory. \code{ld01} asks for the
DL07 model with the Li \& Draine (2001) carbonaceous absorption in place of the
Draine \& Li (2007) one --- everything else the same, so a ratio of the two
curves isolates that one cross section --- and lands beside it as
\code{../data/dl07/kext\_ld01\_MW[\_euv].dat}, with the matching
\code{/kext\_ld01} group inside the model's own product. The 2003 reference
table \code{kext\_albedo\_WD\_MW\_3.1\_60\_D03.all\_2003} was computed
with those cross sections, which is why the point-by-point comparison this
program prints at the end is the sharper test for that run. For astrodust the
\code{euv} floor now falls inside the $Q$ table, so
\code{./calc\_kext.x astrodust} and \code{./calc\_kext.x astrodust euv} cover
the same grid and write the same curve; only the field widths and the header
differ.

Columns are
\begin{center}
\code{lambda[um] \ albedo \ <cos> \ C\_ext/H \ C\_abs/H \ C\_sca/H \ K\_abs}
\end{center}
in \um\ and cm$^2$ per H nucleon, with $K_{\rm abs}$ in cm$^2$/g. The first four
columns are in the order of Draine's \code{kext\_albedo} tables, so a reader
written for those files (for instance the \code{par\%ion\_dust\_kext} reader of
the MoCHII host, which takes four reals from each row and uses $\lambda$, albedo
and $C_{\rm ext}$) parses these unchanged. Note the fifth column differs from
Draine's: his is $K_{\rm abs}$ [cm$^2$/g], ours is $C_{\rm abs}$/H
[cm$^2$/H], so no dust-mass normalization is folded into the first six columns.
$K_{\rm abs} = (C_{\rm abs}/{\rm H})\,/\,(M_{\rm dust}/N_{\rm H})$ is written as
a separate trailing column instead, on every product, because every model states
its grain densities (\S\ref{sec:mass}). The header of each file records the
$M_{\rm dust}/N_{\rm H}$ its $K_{\rm abs}$ column is normalized by and where
that model's densities come from.

After writing, the program checks $C_{\rm ext} = C_{\rm abs}+C_{\rm sca}$ and
the ranges of albedo and $\langle\cos\theta\rangle$, and --- for astrodust and
DL07 --- prints the comparison against the author-provided data of
Table~\ref{tab:refcoverage}.

\paragraph{These files are transport optics, not a dust model.} They carry no
size-resolved $C_{\rm abs}(\lambda,a)$, no grain enthalpy and no Planck
integral, so stochastic heating and thermal emission cannot be computed from
them. A host that needs emission must build the model; the builder reads this
curve back in, \code{dust\_extinction} serves it on the model wavelength grid
and \code{dust\_emission} supplies the re-emitted spectrum, which is what keeps
the absorbed power and the emission referring to one and the same grain.

\subsection{The command-line system}\label{sec:standalone:options}

Every program in \code{sed/} takes ONE vocabulary of run settings
(\code{sed/src/sed\_run\_options.f90}), so that a word names the same physics
whichever program reads it. The settings fall into independent \emph{axes}
(Table~\ref{tab:runoptions}), and each program DECLARES which axes it has a
referent for before it reads a single argument. Three things follow from that
declaration:

\begin{itemize}
\item a word of a declared axis is read;
\item a word of an axis the program did \emph{not} declare is refused, naming
      the axis --- \code{./calc\_kext.x dl07 qm} answers \code{'qm' selects the
      stochastic-solver axis, which calc\_kext has no referent for} --- rather
      than being silently dropped, which is the failure this system exists to
      prevent. When the axis exists in the program but not in the model it was
      asked about, the model is named instead: \code{./calc\_sed.x zubko c2}
      answers \code{\ldots which calc\_sed's zubko has no referent for};
\item anything else is the program's own positional argument (a DL07 submodel
      name, a wavelength floor, a descriptor path).
\end{itemize}

The three \code{qm} words name one solver and one cooling kernel between them:
all three set \code{stoch\_method = 'qm'}, and they set \code{qm\_method} to
\code{'dbdis'} (the default), \code{'dbcon'} and \code{'stati'} respectively
(\S\ref{sec:solver}). They are values of one axis, not two settings, so
\code{qm qm\_stati} is the refusal below rather than a compound request.

Two kinds of combination are refused rather than resolved silently. Naming two
values of one axis --- two solvers, or two graphite sources --- would leave the
run doing one thing and its filename claiming another. So would naming a setting
the chosen solver does not read: \code{nstate=} and \code{nisrf=} size the
energy-space transition matrix, which only \code{qm}, \code{qm\_dbcon} and
\code{qm\_stati} build, and \code{photcut} acts inside the bin sum of the
heuristic narrowing solver, the only solver that reads it.

Every setting tags the output filename, so a variant run cannot overwrite the
production one. Parsing and tagging are separate steps: reading an argument only
records what was asked for, and the tag is assembled afterwards in one fixed
order --- grid, field extent, solver, graphite, optics set, enthalpy, field
normalization, emission term, numerical sizes --- so \code{induced qm} and
\code{qm induced} write the same file. A default run carries no tag at all,
which is what leaves the production filenames as they were. Each program prints
the file it will write before it starts, so a mistyped setting is caught then
rather than after the work.

Where a setting lands is a separate module (\code{sed\_apply\_options.f90}),
because the answer is not the same for every program: one that computes an
enthalpy table or a cross-section table links no solver and no radiation field,
and would otherwise have to drag both in to get the shared command line.

\subsection{\code{calc\_sed.x} --- emission SEDs}\label{sec:standalone:sed}

One program for the shipped models: \code{./calc\_sed.x <model>
[settings \ldots]}, the model name required and everything after it from the
system of \S\ref{sec:standalone:options}. It writes
\code{output/sed\_<model>[\_<submodel>][\_<tag>][\_<stage>].dat}.

\paragraph{\code{astrodust} --- the production SED.} Solves the astrodust+PAH SED for a single Mathis-ISRF cell at $U = 1.585$
($\log U = 0.20$, the HD23 best fit), on a 200-point log $T$ grid from 2.7 to
\SI{5000}{\kelvin}. Reads the T-matrix $Q$ table
\code{../tmatrix/output/q\_astrodust\_P0.20\_Fe0.00\_1.400.dat} and
\code{../data/release/size\_distribution.dat}; writes
\code{output/sed\_astrodust[\_<tag>]\_S1.dat}, \code{\ldots S2.dat} and
\code{\ldots PAH.dat}, each with $\lambda$ [\um] and \lamIlam/\Nh.
Optional arguments, in any order: the shared settings of
\S\ref{sec:standalone:options}, plus the two axes only this model has a referent
for --- the graphite of the PAH $\xi$ blend and the Stage-1 enthalpy prefactor
\code{c2}.

\code{gra\_d03\_sphere}, \code{gra\_d16\_sphere} and \code{gra\_d16\_spheroid}
name the graphite optics the carbonaceous PAH-to-graphite $\xi$ blend takes.
\code{'d16\_sphere'} is the production choice and the HD23 one --- Draine 2016
turbostratic graphite, Maxwell-Garnett effective medium, on a sphere --- and
naming it outright changes nothing. \code{gra\_d03\_sphere} takes the Draine
2003 dielectric functions with Mie on a sphere, weighting $E \parallel c$ by
$\tfrac{1}{3}$ and $E \perp c$ by $\tfrac{2}{3}$, which is the original DL07
choice; \code{gra\_d16\_spheroid} takes the same D16 material on Draine's
$b/a = 1.4$ oblate spheroid table, random-orientation averaged. They tag their
output \code{d03gra\_}, \code{d16gra\_} and \code{sphdgra\_}
(\code{output/sed\_astrodust\_d03gra\_S1.dat} and so on). All three
reach the PAH population only, so the S1 and S2 files they write are
byte-identical to the production ones; what they move is the PAH sub-mm.

\paragraph{\code{dl07} --- the DL07 reference SED.} Solves the Draine \& Li (2007) silicate + carbonaceous SED with the WD01 size
distribution, at $U = 1$ unless \code{logU=X} asks for another intensity.
\code{./calc\_sed.x dl07 [model] [settings \ldots]}, where \code{model} is one of
\code{mw31\_00 \ldots mw31\_60} (default \code{mw31\_60}), \code{lmc2\_00},
\code{lmc2\_05}, \code{lmc2\_10}, \code{smc}; an unknown name is rejected with
the valid list and the settings this driver takes. Those are the shared settings
of \S\ref{sec:standalone:options} plus the graphite of the $\xi$ blend, which
this model computes as well --- its own choice being \code{'d03\_sphere'}.
Writes \code{output/sed\_dl07\_<submodel>[\_<tag>].dat} with columns
$\lambda$, total, silicate and carbonaceous \lamIlam/\Nh.

Naming a graphite source has one further effect here. The stored cross sections
under \code{../data/dl07/} were computed once, with this model's own
\code{'d03\_sphere'} graphite, so reading them back would leave the request with
no effect at all; a named graphite therefore solves every optic from the
dielectric functions instead. That is what a comparison of two graphite choices
needs anyway --- both variants then take the same route --- it costs about a
second on the shipped grid, and \code{gra\_d03\_sphere} reproduces the
stored-table default to every printed digit.

\paragraph{\code{zubko} --- the Zubko/ZDA SED, and the wide-grid
regression.}\label{sec:standalone:zubko} Solves the Zubko, Dwek \& Arendt (2004) BARE-GR-S SED --- PAH + graphite +
silicate, the ZDA size-distribution formula, the ZDA optics and calorimetry
tables --- for a Mathis ISRF at $U = 1$, and writes
\code{output/zubko\_sed\_ours[\_<tag>].dat} with columns $\lambda$,
total, PAH, graphite and silicate \lamIlam/\Nh.
\begin{lstlisting}[style=sh]
./calc_sed.x zubko [settings ...]
\end{lstlisting}
\noindent The settings are the shared vocabulary of
\S\ref{sec:standalone:options}; there is no graphite axis here, because this
model is its distributed optics tables and computes no $\xi$ blend of its own.
The solver defaults to \code{heuristic}, the model default. \code{euv} builds
the model on the whole ZDA optics range, $10^{-3}$\um\ (\SI{1.24}{\kilo
\electronvolt}) upward, instead of cutting it at the Lyman limit where the
Mathis field stops. \code{hardfield} then replaces the field below the Lyman
limit --- where the Mathis field is identically zero --- by a diluted
$10^5\,$K blackbody, so that the field really does carry photons above
$13.6\,$eV; the dilution is chosen so that band deposits roughly as much power
as the whole Mathis field --- enough for the hard photons to matter, little
enough that the small grains still heat stochastically. It implies \code{euv},
a cut grid having no wavelength to put those photons on.

\medskip
\noindent This is the emission counterpart of \code{./calc\_kext.x zubko}, which exercises
only the extinction size integral. It exists because Zubko is the one shipped
model whose optics grid ($10^{-3}$\um) reaches far past the band a transported
field occupies ($0.0912$\um\ for the Mathis ISRF), so anything in the
stochastic-heating path that reads the grid where it should read the field shows
up here and nowhere else. Running it with and without \code{euv} is the
regression of \S\ref{sec:euv-ceiling}.

\subsection{\code{calc\_enthalpy.x} --- enthalpy tables (diagnostic)}

Tabulates $U(T, a_{\rm eff})$ for the two astrodust enthalpy stages and writes
\code{output/enthalpy\_S1.dat} and \code{output/enthalpy\_S2.dat} (201
log-spaced temperatures from 2.7 to \SI{5000}{\kelvin} $\times$ the 169 radii of
\code{../data/astrodust/DH21\_aeff}, $T$ outer and $a$ inner). Its one axis is
\code{c2}, the Stage-1 density-corrected prefactor, which tags its table
(\code{output/enthalpy\_S1\_c2.dat}) and writes no Stage-2 file, Stage 2 not
reading that setting. \textbf{It is not required to compute an SED}: the solver calls the
closed-form Debye sums directly in its inner loop. Use it to compare the two
stages, to plot $U(T)$, or to spot-check against published DL01 values.

\section{The model object and accessors}\label{sec:model}

\begin{lstlisting}
type :: dust_model_t
   character(len=32)              :: name
   integer                        :: NA, NLAM, NT
   real(wp), allocatable          :: lam(:)          ! (NLAM) [um]
   real(wp), allocatable          :: aeff(:)         ! (NA)   [um]
   real(wp), allocatable          :: T_first(:)      ! (NT)   [K]
   real(wp), allocatable          :: log_T_first(:)  ! (NT)
   type(grain_pop_t), allocatable :: pops(:)
   integer                        :: n_channel
   character(len=16), allocatable :: channel_name(:)
   logical                        :: use_induced_emission   ! default .false.
   character(len=16)              :: stoch_method           ! default 'heuristic'
   logical                        :: verbose                ! default .false.
end type
\end{lstlisting}

\noindent Each \code{grain\_pop\_t} in \code{m\%pops} carries its own
\code{aeff}, \code{dn}, \code{Cabs}, \code{Csca}, \code{gsca}, \code{kappB},
\code{H} and \code{kappCMB} (plus cached logs), and the scalar
\code{rho\_bulk} [\,g/cm$^3$\,], the solid density of the material that
population is made of. A model whose components have
different size grids --- Zubko is the case in the tree --- is represented by
populations of different lengths, which is why the solver takes the size count
from \code{size(pops(ip)\%dn)} rather than from \code{m\%NA}.

\paragraph{\code{rho\_bulk}.} It is what turns \code{dn} into a mass, and the
only thing \code{dust\_mass\_per\_H} (\S\ref{sec:mass}) reads besides the size
distribution. For a porous grain it is the density already reduced by the
porosity, i.e.\ mass over the \emph{grain} volume $\tfrac43\pi a_{\rm eff}^3$,
not over the solid volume inside it --- which is why the astrodust value is
$\rho_{\rm Ad} = 2.74$ rather than the $3.425$ of the solid it is made of.
Leaving it at its default $0$ declares that the model states no density, and
that population then contributes no mass.

\paragraph{Diagnostics.} \code{m\%verbose} (default \code{.false.}) keeps the
library solve path silent; set it \code{.true.} to print the same solver
diagnostics as the CLI drivers.

Convenience accessors (all in \code{dust\_lib}):
\begin{lstlisting}
n  = dust_nlam(m)              ! number of wavelengths
nc = dust_n_channel(m)         ! number of output channels
lam = dust_lambda(m)           ! allocatable copy of the wavelength grid [um]
nm  = dust_channel_name(m, ic) ! name of channel ic
\end{lstlisting}

\section{The generic file loader}

\code{build\_from\_files} reads a small text \emph{descriptor} and assembles a
model from data files, with no code changes. One \code{pop:} line per
population:
\begin{lstlisting}[style=sh]
# data/zubko/zubko_descriptor.txt
name = zubko_bare_gr_s
# pop: <grain_type> <channel> <optics> <dnda_table> <calorimetry> <rho(0=use file)>
pop: pah 1 PAH_28_1201_neu.dat  ZDA_BARE_GR_S_SzDist_PAH.dat Graphitic_Calorimetry_1000.dat 0.0
pop: gra 2 Gra_121_1201.dat     ZDA_BARE_GR_S_SzDist_Gra.dat Graphitic_Calorimetry_1000.dat 0.0
pop: sil 3 suvSil_121_1201.dat  ZDA_BARE_GR_S_SzDist_Sil.dat Silicate_Calorimetry_1000.dat  0.0
\end{lstlisting}
\begin{itemize}
\item \code{grain\_type}: \code{'sil'}, \code{'pah'}, or \code{'gra'} (selects the
      heat-capacity/mode model used by the \code{'qm'} solver; ignored by the GD
      solvers, which use the supplied enthalpy directly).
\item \code{channel}: integer output channel ($1\dots$); populations sharing a
      channel are summed.
\item \code{optics}: a ZDA $Q$-table ($Q_{\rm abs}$ per radius and
      wavelength); $C_{\rm abs}=Q_{\rm abs}\pi a^2$.
\item \code{dnda\_table}: a 2-column table $a$ [\um] and ${\rm d}n/{\rm d}a$
      [cm$^{-1}$ H$^{-1}$].
\item \code{calorimetry}: a specific-enthalpy table $u(T)$ [erg/g];
      $H(T,a)=u(T)\,\rho\,\tfrac{4\pi}{3}a^3$.
\item \code{rho}: grain density [g\,cm$^{-3}$]; \code{0.0} uses the value in the
      optics-file header.
\end{itemize}
All files are sought under \code{data\_dir}. The coded builders
(\code{build\_astrodust}/\code{dl07}/\code{zubko}) are the recommended path for
the built-in models; \code{build\_from\_files} is for adding new data-defined
models.

\section{Linking into a 3D RT code}

Compile your RT source against the one archive, with the \code{.mod} search path
pointing at \code{SEDust/sed/}:
\begin{lstlisting}[style=sh]
gfortran -I<sed> my_rt.f90 -L<sed> -lsedust -fopenmp -o my_rt.x
\end{lstlisting}
The line is the same whether or not the T-matrix was built in
(\S\ref{sec:build}): \code{WITH\_TMATRIX=1} puts the T-matrix objects into
\code{libsedust.a} itself, so the host never names a second archive. The archive
needs no OpenMP runtime of its own --- the threading is on the SEDust side ---
so \code{-fopenmp} is required only because \code{libsedust.a} uses it.

Only an astrodust EUV band (\S\ref{sec:euv-shape}) ever reaches the T-matrix ---
and the shipped $Q$ table leaves no such band to compute --- and it reaches it
through a procedure the host registers rather than a compiled
dependency, which is why the plain archive links without one. A host with its
own spheroid solver can register that instead: \code{sed\_register\_euv\_band\_optics}
takes any procedure matching the abstract interface \code{euv\_band\_optics\_i}
(both re-exported by \code{dust\_lib}), and
\code{sed\_forget\_euv\_band\_optics} undoes it.

A complete minimal example is provided in
\code{SEDust/sed/rt\_example/use\_dustlib.f90}: it builds a model, computes
emission for one field, and prints the SED peak. No \code{ISO\_C\_BINDING} is
needed --- the RT code simply \code{use}s the Fortran module \code{dust\_lib}.

\paragraph{Threading.} \code{m} is read-only during \code{dust\_emission}; all
scratch is local. The solver uses OpenMP internally over grains. If your RT
parallelizes over cells, take care to avoid oversubscription (nested
parallelism); the default \code{'heuristic'} solver is serial per call, which
suits an outer cell-level parallel loop.

\section{Units and conventions}

\begin{itemize}
\item Wavelengths \code{lam} are in \um\ throughout; cross sections in cm$^2$.
\item \code{J\_lam} is a mean intensity with the same units as the Planck
      function $B_\lambda$ (specific intensity per steradian). The library's
      output \lamIlam$/\Nh$ is then in
      erg\,s$^{-1}$\,cm$^{-2}$\,sr$^{-1}$\,H$^{-1}$.
\item The CMB (2.725\,K) is included in the heating field by \code{J\_Mathis}.
\item The induced-/stimulated-emission factor is off by default (the output is
      \emph{net} emission, matching the HD23 and DL07spec released SEDs).
\end{itemize}

\section{The HDF5 optics products}\label{sec:hdf5}

Every model's optics ship as one HDF5 file,

\begin{center}
\code{data/astrodust/sedust\_astrodust.h5} \quad \code{data/dl07/sedust\_dl07.h5}
\quad \code{data/zubko/sedust\_zubko.h5}
\end{center}

\noindent holding that model's wavelength axis, its $(\lambda, a_{\rm eff})$
cross-section tables and its size-integrated extinction curve. One file per
model, because the models share no grid, no radius grid and no component list,
and because a host ships only the models it runs. This is the primary form; the
text products (\S\ref{sec:data}) are still written beside it and stay readable
with an eye and diffable.

\subsection{One wavelength axis, and what \code{include\_euv} means}

Each file carries \emph{one} wavelength axis --- the widest the model has ---
and records \code{i\_lyman}, the index of the \emph{last} wavelength at or
shortward of the Lyman limit, $0.0912$\um:

\begin{lstlisting}
/                   attrs: model, generator, layout
/grid/lambda        (n_lam) [um], strictly increasing
/grid               attrs: i_lyman, lambda_lyman_um, i_lyman_meaning
/kext/{albedo,g,C_ext,C_abs,C_sca,K_abs}          (n_lam)
/kext               attrs: M_dust_per_H, size_dist_file, text_product, method
/qtable/<comp>/a_eff                              (n_a) [um]
/qtable/<comp>/{Q_ext,Q_abs,Q_sca,g}   (n_lam, n_a) Fortran = (n_a, n_lam) in h5py
/qtable/<comp>/regime    astrodust only: 0 T-matrix, 10 Rayleigh, 20 geometric optics
/qtable/<comp>      attrs: rho_bulk_g_cm3, method, source, scatters
\end{lstlisting}

A reader given \code{include\_euv = .false.} --- the default --- returns
\code{lambda(i\_lyman:)} and the same slice of every wavelength-indexed array;
\code{.true.} returns the whole axis. The narrow product is therefore a
\emph{view} of the wide one rather than a second file to keep in step with it:
the two cannot disagree, and there is nothing to regenerate twice. That is what
replaces the paired \code{*\_euv.dat} text products. The cut is an HDF5
hyperslab, so a non-ionizing host reads only the rows it keeps.

Measured \code{i\_lyman}: astrodust 634 of 1762, DL07 695 of 1823, Zubko 336 of
1201 --- giving 1129, 1129 and 866 non-ionizing wavelengths, the lengths of the
corresponding text products.

The rule is the \emph{last} node at or below the limit, not the first at or
above it, because the non-ionizing view is a table an RT host interpolates onto
its own grid: it has to \emph{cover} the band the host transports. The
astrodust and DL07 axes carry $0.0912$\um{} exactly, so for them the two rules
return the same index. The ZDA grid does not, and its first node above the
limit sits $1.2\times10^{-5}$ of itself inside it --- just past
\code{dust\_extinction}'s edge allowance, so the same call that was served for
two models used to be refused for the third. One extra node of the model's own
table is not extrapolation; widening the allowance instead would have weakened
the guard for every model at every wavelength.

\subsection{Zubko carries two sets of optics}\label{sec:zubkooptics}

The ZDA BARE-GR-S model is defined by Zubko, Dwek \& Arendt (2004), and the
paper is where it would have to be read from. What this tree ships beside it
are the three grain-input files the Camps et al.\ (2015) benchmark
distributes ---

\begin{lstlisting}
data/zubko/suvSil_121_1201.dat   data/zubko/Gra_121_1201.dat
data/zubko/PAH_28_1201_neu.dat
\end{lstlisting}

\noindent byte-identical to \code{SHG\_Benchmark/DustModel/GrainInputs/} ---
so that the participating codes all run one agreed reproduction. Their headers
record how they were made: Zubko's multilayer-sphere code (1997--2002),
converted by K.~Misselt in 2002, for the silicate and graphite; a 2009
implementation by Misselt of Li \& Draine (2001) / Draine \& Li (2007) for the
PAHs.

Those files are the \textbf{default}. They are stored in \code{/qtable} of the
product as they stand --- \code{check\_build\_dust.x} reads both sides and
requires an exact match --- so a run against that benchmark measures the
stochastic-heating solver and not an optics difference. This tree's own
recomputation, Mie on the Draine (2003) optical constants, sits beside them
under names suffixed \code{\_mie\_d03}, and each set has its own extinction
curve so that what \code{dust\_extinction} serves is the size integral of the
very optics the model was built on:

\begin{lstlisting}
/qtable/{sil,gra,pah}                  the benchmark's tables      <- default
/kext                                    ... and their size integral
/qtable/{sil,gra,pah}_mie_d03          Mie on the D03 constants
/kext_mie_d03                            ... and their size integral

call build_dust(m, 'zubko', '../data', status=st)                          ! default
call build_dust(m, 'zubko', '../data', status=st, zubko_optics='mie_d03')
\end{lstlisting}

\noindent \code{build\_zubko} takes the same choice as \code{optics}, and
\code{calc\_kext.x zubko [euv] [zda|mie\_d03]} writes the matching curve. A
name that is neither is refused (\code{build\_zubko} status 8,
\code{build\_dust} status 92) rather than silently defaulted.

The recomputation reproduces the distributed silicate to a mean relative
$2.4\times10^{-6}$ and the graphite to 0.45\% in $Q_{\rm sca}$ and 8\% in
$Q_{\rm abs}$. Its PAH component is a different implementation of the same
LD01/DL07 prescription; measured against \code{Gra\_121\_1201.dat} cell by
cell, the distributed PAH file holds graphite $Q_{\rm sca}$ and $\langle\cos
\theta\rangle$ at every size and all 1201 wavelengths, and graphite $Q_{\rm
abs}$ shortward of $0.0585$\um{} (21.2\,eV, the DL07 PAH-to-graphite
transition), so the ZDA PAHs scatter as the graphite sphere of their own
radius. The recomputation now does the same. Through one builder and one size
distribution the two sets differ by at most 0.17\% in $C_{\rm sca}$ and 8.4\%
in $C_{\rm abs}$, the latter in the far-infrared where the graphite $Q_{\rm
abs}$ discrepancy sits.

\subsection{\code{build\_dust}: one entry point}

\begin{lstlisting}
use dust_lib, only: dust_model_t, build_dust
call build_dust(m, 'zubko', '../data', include_euv = .false., status = st)
\end{lstlisting}

\noindent One call for \code{'astrodust'}, \code{'dl07'}, \code{'zubko'} and
\code{'from\_files'}, built from one directory and one flag:

\begin{lstlisting}
call build_dust(m, model, data_dir [, NT, T_lo, T_hi] [, include_euv] [, status] &
                [, message] [, lam_min] [, kext_path] [, sd_index] [, u_isrf] &
                [, zubko_optics] &
                [, config_path] [, astrodust_index_path] &
                [, euv_tmatrix])
\end{lstlisting}

\code{NT}, \code{T\_lo} and \code{T\_hi} are the internal temperature grid
and are optional, defaulting to \code{200, 2.7, 5000} --- the values the rest of
this manual quotes as typical. They are what the EMISSION is solved on: the
enthalpy $H(T,a)$ and the Planck-averaged opacity $\kappa_B(T,a)$ are tabulated
on that grid, \code{calc\_Teq} interpolates $T_{\rm eq}$ in it, and the
stochastic solver's window is CLAMPED to $[T_{\rm lo}, T_{\rm hi}]$ rather than
extrapolated past it --- so the range must bracket the temperatures the field
produces, and \code{NT} sets how finely $T_{\rm eq}$ is resolved. The extinction
reads none of it, so a host that only wants \code{dust\_extinction} can leave
all three out.

\code{data\_dir} is the SEDust data directory. The optics come from
\code{data\_dir/<model>/sedust\_<model>.h5} --- the wavelength axis, the cross-section
tables and the extinction curve alike. What is \emph{not} optics still comes
from beside it: the size distribution
(\code{data\_dir/release/size\_distribution.dat}, or the ZDA config) and the
calorimetry.

\code{include\_euv} and \code{lam\_min} each mean \emph{one} thing, for every
model. \code{include\_euv} selects the view: \code{.false.} cuts the model's own
axis at \code{i\_lyman}, so the grid a host gets covers the Lyman limit whatever
model it named. \code{lam\_min} states the shortest wavelength the model must
\emph{cover}, and never truncates: astrodust and DL07 meet it by extending on
the dielectric function their optics come from, while Zubko and a file-defined
model, which have no dielectric function behind their tables, meet it when
those tables already reach and \emph{refuse} it when they do not.

Both used to be model-dependent, and a host with one call and one physically
motivated floor met the difference: \code{include\_euv} was an index cut for two
models and a wavelength cut for the third, and \code{lam\_min} extended two
models and truncated the other two.

The builders of \S\ref{sec:models} are unchanged and still exported, so a
host that names its own files keeps working. Two of them gained an optional
argument that \code{build\_dust} uses: \code{include\_euv} on
\code{build\_astrodust} (which axis to take out of an HDF5 $Q$ table) and
\code{lam\_axis} on \code{build\_dl07} (the model's wavelength axis outright).
The second is why a host running DL07 alone needs no astrodust product: that
model takes only a \emph{grid} from a $Q$ table, so \code{build\_dust} hands it
\code{/grid/lambda} out of \code{sedust\_dl07.h5} and no $Q$ table is opened.

\subsection{The existing builders take an HDF5 path too}

Every place that names an optics file dispatches on the \code{.h5} suffix, so no
caller needs a second flag to say which form it meant:

\begin{lstlisting}
call build_astrodust(m, '../data/astrodust/sedust_astrodust.h5', NT, T_lo, T_hi, &
                     status=st, include_euv=.false.)
\end{lstlisting}

\noindent The same holds for \code{kext\_path}. And with \code{kext\_path}
absent, a builder now tries \code{../data/<model>/sedust\_<model>.h5} \emph{first} and
falls back to the text default listed in Table~\ref{tab:kext}, and reads it
the same way. \code{/kext} is read on
the \emph{whole} wavelength axis, never the non-ionizing slice: the curve is
interpolated onto the model grid, so the widest one covers every grid the model
can be built on. This is what retires the pairing of a narrow model with an
\code{\_euv}-only table, which used to fail at \code{dust\_extinction} rather
than at the build.

\subsection{Generating them}

\begin{lstlisting}
cd sed
./calc_qtable.x            # /grid and /qtable, every model
./calc_kext.x <model> euv  # /kext, for each of the three
\end{lstlisting}

\noindent \textbf{The order matters.} \code{calc\_qtable.x} lays down the
wavelength axis, so it creates the file with \code{H5F\_ACC\_TRUNC} and
\code{/kext} goes with it; the \code{euv} run of \code{calc\_kext.x} puts it
back. That is the only order in which the two can be consistent, since a curve
integrated on the previous axis would be filed against wavelengths it was not
computed at. \code{calc\_qtable.x} says so on stdout, and \code{calc\_kext.x}
writes \code{/kext} only if the grid it integrated on equals \code{/grid/lambda}
to $10^{-12}$.

\subsection{Reading them from Python}

\code{pyutil/sedust\_h5.py} is the counterpart of the Fortran reader: same file,
same cut, same numbers.

\begin{lstlisting}
from pyutil.sedust_h5 import read_grid, read_kext, read_qtable, describe

k = read_kext('data/zubko/sedust_zubko.h5')                 # non-ionizing, 866 points
q = read_qtable('data/dl07/sedust_dl07.h5', 'sil', include_euv=True)
describe('data/astrodust/sedust_astrodust.h5')   # or: python -m pyutil.sedust_h5 <file>
\end{lstlisting}

\noindent The cut comes from the file's own \code{i\_lyman}, never from a
wavelength comparison of the reader's own, so Fortran and Python slice at the
same node. Cross sections come back \code{(n\_a, n\_lam)}: Fortran declares them
\code{(n\_lam, n\_a)} and HDF5 stores them in that order, so each grain radius is
one contiguous spectrum and the wavelength is the last axis. Nothing is
computed on read --- a value the file does not carry comes back \code{None},
never a zero that could be mistaken for a computed one.

\subsection{Building without HDF5}

\code{make HDF5=0} (and \code{HDF5=0 ./build\_lib.sh}) compiles the HDF5 paths
out. Every entry point of the layer then reports ``not available'' through its
\code{ok} argument and the callers fall through to the text products, so no
consumer carries an \code{\#ifdef} and nothing has to be configured away. The
same happens at run time in a tree that simply has no products yet. A default
archive references the HDF5 libraries, so a host linking it must put
\code{-lsedust} \emph{before} them: a static archive resolves left to right, and
it is \code{libsedust.a} that needs those symbols.

\section{Data files}\label{sec:data}

Model data lives under \code{SEDust/data/}, in \textbf{one directory per
model} plus what the models share:
\begin{itemize}
\item \code{astrodust/}, \code{dl07/}, \code{zubko/} --- everything that
      model owns: its HDF5 product \code{sedust\_<model>.h5}
      (\S\ref{sec:hdf5}), the same optics as text (\code{q\_*.dat},
      \code{kext\_*.dat}), and, where the model IS a set of files, its
      definition. For astrodust that includes the T-matrix $Q$ tables and the
      orientation-resolved DH21 table with its \code{DH21\_wave} /
      \code{DH21\_aeff} axes; for Zubko, the ZDA config/formula, the tabulated
      size distributions, the ZDA $Q$-tables and the calorimetry tables from
      the Camps et al.\ 2015 benchmark (a ready descriptor is
      \code{zubko\_descriptor.txt}).
\item \code{dielectric/} --- shared material data: the DH21 astrodust index
      \code{index\_DH21Ad\_P0.20\_0.00\_1.400} (which the astrodust $Q$ table
      was computed from, and which fixes how far \code{lam\_min} may reach),
      the D03 astrosilicate and graphite indices, the D16
      turbostratic-graphite tables, and the PAH cross sections. A dielectric
      function belongs to no one model --- DL07 and Zubko read the same D03
      astrosilicate --- so it does not sit inside a model directory.
\item \code{release/} --- the published reference tables and the HD23 size
      distribution (\code{size\_distribution.dat}), which astrodust and DL07
      share.
\end{itemize}

\noindent The rule is that a host ships \code{data/<model>/} for each model it
runs, plus \code{dielectric/} and \code{release/}. \code{build\_dust} takes
\code{data\_dir} and resolves the rest, so nothing names a product file.
